# 结论体系 v2.1 说明（问题类型 × 结论等级）

## 1. 为什么要改

旧版只有一列 `AI定性结论`，把两个不同的问题混在一起：

- 这两张图到底是哪种问题（同一家店拿旧图交差？还是把 A 家的图拿去交 B 家？）
- 这个结论有多确定（铁证？还是只是像？）

结果是无法直接排作业：不知道哪些可以直接审定，哪些必须人工看。
所以拆成两列：**问题类型**（是什么问题）+ **结论等级**（有多确定）。

## 2. 问题类型（四取一）

| 类型 | 含义 | 判定条件 | 严重度 |
| --- | --- | --- | --- |
| 类型A-跨期复用旧图 | 同一家店，旧照片拿到新任务重复交差 | 商户名相同或地址一致 + 完成时间相差 > 7 天 + 同一底片 | 中高 |
| 类型B-跨主体套用 | 把别家店的照片拿来充本家店 | 商户名不同 **且** 地址判定不一致 + 同一底片 | 最高，优先复核 |
| 类型C-同次连拍分摊 | 一次到店连拍多张，分摊到多个任务 | 同商户/同地址 + 时间差很小 + 高度相似 | 默认不计入问题队列（可开关） |
| 无问题 / 待定 | 同任务、同周期、或信息不足 | 见代码规则 | - |

时间一律取结构化完成时间字段，**绝不读图内水印时间**。

## 3. 结论等级（五档）

| 等级 | 谁能给 | 处理方向 |
| --- | --- | --- |
| 确认 | 只能由确定性算法给：pHash 距离≤阈值（默认 0）且 ORB 内点≥阈值（默认 30），同时业务条件成立 | 可直接进入审定流程，建议 10% 抽核 |
| 高度疑似 | AI 建议同一底片 + 业务条件成立 | 必须人工复核 |
| 待核实 | 信息不足、调用失败、模型与算法结论冲突 | 补数据或人工判断 |
| 正常 | 同任务、同周期，或 AI 判定真实重拍 | 不入问题库 |
| 算法误报 | AI 判定为不同商户/不同场景 | 回流校准哈希阈值与地址规则 |
| 未抽检 | 还没进入 AI 抽检队列 | 排队 |

两条硬规矩：

1. **大模型永远不能给“确认”**，最高只能给“高度疑似”。
2. **结论不等于处罚**。每行都留 `人工终审结论` / `终审人` / `终审时间` 空列。

## 4. 代码入口

| 文件 | 作用 |
| --- | --- |
| `conclusion_engine.py` | 结论引擎：字段识别、类型归类、等级判定、统一输出列 |
| `apply_conclusions.py` | 命令行：对已有 xlsx 追加结论列，并导出确认/高度疑似/误报三张清单 |
| `data_processor.py` | GUI 导出：抽检报告与“原表追加副本”都自动带上结论列 |
| `ai_client.py` | 模型调用：可复现、可审计、可缓存 |

### 常用命令

```bash
# 默认口径（7 天窗口，类型C 不计入问题队列）
python3 apply_conclusions.py --input 照片相似候选_100k_7天窗口_地址一致性判断.xlsx

# 跨期口径收紧到 30 天
python3 apply_conclusions.py --input xxx.xlsx --window-days 30

# 同店同周期连拍也要看（启用类型C）
python3 apply_conclusions.py --input xxx.xlsx --count-same-day-burst
```

## 5. AI 调用的可靠性修复（ai_client.py）

| 问题 | 旧版 | 新版 |
| --- | --- | --- |
| 结果不可复现 | `temperature=0.1` | 固定 `temperature=0`、`top_p=1`，并记录 `prompt版本`/`模型版本` |
| 遮蔽太粗暴 | 固定遮蔽底部 20%（3120×4160 约 830px，会遮掉台阶、电瓶车等关键细节） | 自适应探测水印文字带（6%~28% 间 clamp），并回写实际`遮蔽比例` |
| 返回缺字段静默当正常 | 无校验 | 必填字段校验 + 不合规重试一次，失败记`调用状态`并归为待核实 |
| 无法复查 | 不保留原始返回 | 保留 `raw_response`（截断）、图片 sha1、尝试记录 |
| 重跑就重复花钱 | 无缓存 | 按「模型 + prompt + 遮蔽后图片哈希」缓存，幂等、可断点续跑 |
| 稳定性未知 | 无 | `consistency_check=True` 重复调用一次，输出「重复调用一致性」 |
